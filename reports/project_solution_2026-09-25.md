# AuTo_LaTeX 产品与架构改进方案

日期：2026-09-25。依据：[现状对比](project_chatgpt_analysis_2026-09-25.md)及当前代码。目标是在保留本地数学工具和可验证工作流的前提下，让用户能直接发出学习、计划与讨论指令，并在长期使用中得到稳定且可纠正的个性化体验。原 P0 至 P4 已完成代码接线；本次又落地了交互方式更新、自动方式确认、计算脚本沙盒和对话分组/删除。LLM 端到端与本机提醒/OCR 尚未验证。

## 目标体验

1. **学术学习**：用户拖入资料或直接发一段证明，可选讨论、直接或探索；复杂数值计算必须通过脚本运行并核对实际输出。系统沿用课程要求的方法，指出具体错误位置，并在需要时附来源页码或段落。
2. **生活计划**：用户说“周三前完成两章，每晚提醒我”，系统展示可确认的任务、时间和重复规则；完成、延期和回顾都能更新同一事项。
3. **复杂讨论**：用户可以直接提问并持续追问；系统记录核心论点、证据、反例与未决项，长讨论或需要产物时才切换到专家工作流。

## 优先级与最小实现

| 阶段 | 改动 | 复用现有代码 | 完成标准 |
| --- | --- | --- | --- |
| ✅ P0：直接对话 | Super 默认先直接回应；只有多工具、文件产物或长任务再调用专家/工作流。交互方式改为自动、讨论、直接、产出、探索。 | `settings.json`、`src/personalization.py`、`src/web_ui.py`、`src/web_ui.html`。 | 手选模式注入本轮上下文；自动模式必须先审阅进度并等待用户确认。 |
| ✅ P1：偏好闭环 | 使用 SQLite 单独保存偏好内容、适用场景、来源标记、创建/更新时间和启用状态。稳定偏好候选经 y/n 确认后保存；按本轮方式与请求场景注入。提供查看、修改、停用、导出；可用自然语言工具或 `/preferences` 命令管理。 | `src/persistence/store.py`、`src/personalization.py`、`src/tools_registry.py`、Bus 的确认输入。 | 用户明确表达稳定偏好后候选需经确认；新会话读取已确认规则；当前模式覆盖长期规则；用户能修改或停用。当前实现不会从重复行为被动推断偏好，也未做模型端到端验证。 |
| ✅ P2：学习材料入口 | 本地网页可选文件或拖入；后端验证 PDF/PNG/JPG 文件签名和大小，写入 `.gitignore` 覆盖的 `imports/`，本次发送绑定受控文件 ID。PDF 页码从 1 起，OCR 返回原页码和逐页文本。 | `src/web_ui.py`、`src/web_ui.html`、`src/Visal.py`、`imports/`、`OCR_result/`。 | 每条消息最多 5 个文件、每个不超过 20 MB；无需复制路径；PDF 用户页码可定位。复杂版面与段落框坐标暂不返回。 |
| ✅ P3：结构化计划 | 新增 SQLite `tasks` 表记录标题、UTC 到期时间、本地时区、状态、重复方式、来源及上次提醒时间；新增自然语言工具、`/tasks`、`/task complete`、`/task defer` 和进程内 30 秒调度。修改均经用户确认。 | `src/persistence/store.py`、`src/tools_registry.py`、`src/plan.py`。 | 持久化事项；单次提醒事务标记避免重复；daily/weekly 按本地时区推进；停止提醒即完成。仅在程序运行时触发，程序关闭时不会后台推送。 |
| ✅ P4：讨论状态 | Super 与 terminal 统一用 `ConversationStore` 持久化会话；100 个用户轮次后把较早轮次整理为带消息编号的滚动摘要，每新增 20 个较早轮次更新；上下文保留摘要和最近 40 轮。注册 `view_discussion_source` 回查原始消息。 | `src/discussion.py`、`src/persistence/store.py`、`src/super.py`、`src/terminal.py`、`src/tools_registry.py`。 | 原始对话不裁剪；摘要覆盖位置按分支保存；摘要来源可回查。首次摘要生成失败时使用完整历史；已有摘要更新失败时沿用旧摘要，并隔 20 轮重试。 |
| ✅ P5：计算沙盒 | 注册 `run_python`，用受限 AST、标准数值模块白名单、子进程、执行时限和输出/集合上限，让 Agent 编写脚本并查看真实输出。复杂精确计算的 system context 与数学专家提示词明确要求调用它。 | `src/python_sandbox.py`、`src/tools_registry.py`、`src/personalization.py`、`settings.json`。 | 离线脚本、拒绝 OS 导入及结果/时间上限测试通过。它不是操作系统级恶意代码隔离；暂不支持任意第三方包。 |
| ✅ P6：对话整理 | 侧栏按用户自定分组显示对话；支持重命名、移动分组和确认后删除。分组保存在 SQLite；删除会级联清理消息和摘要，删除当前对话前先切换到其他对话，至少保留一个。 | `src/web_ui.html`、`src/web_ui.py`、`src/super.py`、`src/terminal.py`、`src/persistence/store.py`。 | 分组持久化、消息/摘要级联删除、活动会话安全切换均有离线检查。 |

P0 至 P6 的代码路径现已接线。自动模式由 LLM 检查最近十条对话、滚动摘要和当前请求，推荐一个具体方式并等待用户确认或改选。探索方式参考“探索思路与代码方案”对话：从当前进度开始，用容易跟上的语言逐步讨论；先谈算法设计，等用户准备好再试验或写代码。计算沙盒只开放 `math`、`statistics`、`decimal`、`fractions`，拒绝文件、网络和进程相关导入；脚本上限为 12,000 字符、5 秒运行、20,000 字符输出和 16 MB 集合数据。由于没有操作系统级内存隔离，不应将其用于运行不可信恶意脚本。文件上传受扩展名、签名和体积限制；SQLite 记录任务、确认偏好、会话分组与摘要；ChromaDB 继续用于语义记忆。偏好保存用户可审查的规则；一次性请求和重复行为都不会自动变成永久偏好。[ChatGPT 官方记忆说明](https://learn.chatgpt.com/docs/customization/memories)也将记忆定位为辅助召回层，要求固定规则另行保存。

## 三类场景的具体流程

### 学术学习

用户上传资料或给出当前证明 → 选择“讨论/直接/探索”或使用自动建议 → 需要数值验证时，数学 Agent 编写并运行脚本 → 根据输出解释结果和关键步骤。用户要求文档时，才调用 MathWrite、`check_latex`。OCR 引用应标明页码；推论与原文事实分开。一次“给完整证明”只覆盖当前轮，不改长期学习偏好。

### 生活计划

自然语言请求 → 模型调用 `create_task` 形成含本地时间/时区/重复规则的结构化参数 → Bus 展示调用参数并询问确认 → SQLite 保存 → 本地调度器每 30 秒检查 → 单次到期事务标记；重复任务按本地时区推进 → 用户用 `/tasks` 查看、完成或延期。`plan/YYYYMMDD.md` 和 `general.md` 仍用于自由格式计划记录，不是提醒任务状态源。程序关闭时不会后台推送；日历连接仍属后续工作。[官方定时任务说明](https://learn.chatgpt.com/docs/automations)

### 复杂问题讨论

直接回答并标注假设 → 在消息中维护论点/证据/反例/未决项 → 当用户要求“形成报告/核查资料/写 LaTeX”时再建立工作流 → 每阶段保存输入、产物、验收结果。当前 `run_workflow` 的“含验收关键词”检查只是规划门槛，不能代替内容质量验证；应让验收阶段读取可定位的产物并执行实质检查。用户在同一项目里跨会话使用资料的体验可参考 [ChatGPT 项目说明](https://learn.chatgpt.com/docs/projects)。

## 技术边界与实施注意

- **保留现有强约束**：`CapabilityGateway.execute()` 的执行授权、专家白名单、危险工具确认和 Resident 的“校验后提交游标”不能因优化交互而绕开。
- **只读授权已收紧**：`math` 提示词与执行白名单一致，不含 `str_replace_editor`。
- **会话存储已统一**：Super 和 terminal 都使用 `ConversationStore`；`discussion_summaries` 外键关联各分支。
- **区分三种存储**：原始对话存 SQLite；用户确认的偏好单独存且有版本/适用范围；可检索资料及课程笔记可继续用向量检索。三者均可回查原始来源。
- **避免任务过载**：单轮问答使用直接对话；有明确交付物、多工具或副作用时采用工作流；具体阈值应由少量真实任务评估，而非只按关键词硬编码。
- **评估方式**：每阶段至少用“证明只核对一步”“资料 OCR 后定位页码”“跨会话沿用偏好”“重复提醒重启后只触发一次”“长讨论纠正旧论点”五类场景作回归。记录用户操作次数、错误路由率、偏好误用率与任务完成率。

## 已落地实现与验证边界

网页和终端入口接受五种交互方式。Super 对简单请求直接回答，专家调用和显式工作流仍保留。偏好与提醒状态修改需要确认；删除对话前会在网页确认。网页可上传受限 PDF/图片并让 OCR 回传原页码。Super 和 terminal 会话均恢复自 SQLite，长讨论压缩只影响送给模型的上下文，不删除存档。数学专家拥有计算脚本工具但没有文件编辑工具。

本次验证通过：`tests.test_python_sandbox`、`tests.test_personalization_modes`、`tests.test_web_ui`、`tests/test_discussion_history.py`、`tests/test_memory_context.py`、`tests/test_light_mode.py`、`tests/test_runtime.py`。自动判断单测使用模拟模型，不代表当前模型端点的实际建议质量已验证。提醒程序关闭期间不运行；OCR 只有标准启动模式可用；长摘要需要可用的模型端点。
