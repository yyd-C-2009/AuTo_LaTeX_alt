# AuTo_LaTeX 与 ChatGPT 用户端功能差异分析

日期：2026-09-25。范围：本仓库当前实现与 ChatGPT 用户端在**学术学习、生活计划管理、复杂问题讨论**中的使用体验。比较的是产品能力与交互方式，不比较底层模型智力；ChatGPT 功能会随账号、地区和工作区设置变化。

## 1. 本项目实际提供什么

项目通过 `super.py` 或 `terminal.py` 启动本地网页界面，把自然语言请求交给兼容 OpenAI 接口的模型。Super 可调用数学、LaTeX、篇章、TikZ、转写、笔记专家；公共工具包括本地 PDF/图片 OCR、音频转写、Chroma 向量记忆、Markdown 计划、网页查询和文件编辑。工具执行由 Bus 管理，复杂任务可走顺序工作流，常驻笔记可在独立 LaTeX 校验后提交转写游标。技术细节见 [开发者入门](../docs/DEVELOPER_GUIDE.md)。

本地计算不等于整条对话离线：OCR、语音和向量检索可在本机运行，日常对话仍通过 `settings.json` 指定的远程模型端点。

## 2. 三类场景对比

| 场景 | 本项目的长处 | 与 ChatGPT 用户端的主要差距 | 用户可感知结果 |
| --- | --- | --- | --- |
| 学术学习 | Pix2Text 识别公式；数学专家讨论；LaTeX/TikZ 产物可编译检查；课堂音频能进入笔记流程。 | 本地网页只接收文本，没有文件上传入口；用户通常要准备文件路径。固定专家提示词偏向“完成任务”，缺少由用户选择的逐步提示、只核对一步、不给答案等学习模式。OCR 与检索结果也尚未形成统一的页码/来源证据链。 | 项目适合“把资料变成可检查的数学文档”；ChatGPT 直接附上 PDF/图片后继续提问的门槛更低。[ChatGPT 官方文件说明](https://learn.chatgpt.com/docs/use-chatgpt)列出文档、PDF、图片等附件支持。 |
| 生活计划管理 | `Plan` 能按日期追加/查看计划，长期事项存在 `plan/general.md`，文件由用户直接持有。 | 当前主要是 Markdown 增补和查看；没有结构化任务状态、优先级、重复规则、到期提醒、日历冲突检测或跨日回顾。 | “明早提醒我复习”在项目中不能自然落成可靠提醒；ChatGPT 用户端可用自然语言建立定时任务和提醒，具体可用性取决于账号与设置。[官方定时任务说明](https://learn.chatgpt.com/docs/automations) |
| 复杂问题讨论 | Super 能调用专家与顺序工作流；权限护照限制阶段工具；`terminal.py` 有分支会话和 SQLite 消息记录。 | 专家调用每次创建新 Agent，仅接收抽取的近 50 条纯文本对话或上阶段文本结果；没有统一的论点、证据、反例、未决问题状态。Super 的系统提示要求先规划并设验收，简短讨论也会承受调度开销；`super.py` 的分支尚只在内存中。 | ChatGPT 用户端可直接追问、调整方向，并用项目保存相关聊天、文件、指令与来源；本项目多轮深谈需要更多人工维护上下文。[官方项目说明](https://learn.chatgpt.com/docs/projects) |

## 3. 为什么 ChatGPT 用户端显得更直接

ChatGPT 的典型起点是“描述结果并附上材料”，后续用自然语言继续修改或追问；项目和文件可共用上下文，语音在支持的客户端可直接用于继续对话。[基础使用](https://learn.chatgpt.com/docs/use-chatgpt)、[项目](https://learn.chatgpt.com/docs/projects)、[语音](https://learn.chatgpt.com/docs/features/voice)均有官方说明。本项目虽然也接受自然语言，但用户先要完成安装、模型下载、API 密钥、服务启动；文件和音频还需由工具按路径访问。`super.py` 当前提示词规定“先澄清、再计划、必须有独立验收阶段”，这适合可交付任务，对“这一步证明对吗”一类直接提问则偏重。

ChatGPT 用户端还有可选择的模型与推理强度、网页检索、附件和多步骤 Work 流程。[官方网页端说明](https://learn.chatgpt.com/docs/web)、[网页检索说明](https://learn.chatgpt.com/docs/web-search)。项目可替换兼容模型端点，也有自建网页查询工具，但尚未把这些入口整合成同样顺手的对话操作。

## 4. 长期使用后“符合习惯”的差异

ChatGPT 的自定义指令、项目指令和可用时的记忆能把稳定偏好带到后续会话；用户可在设置中管理记忆。记忆是否启用以及能覆盖哪些会话由产品与账号设置决定，不应视为每句话都会被永久记住。[个性化设置](https://learn.chatgpt.com/docs/reference/settings)、[记忆说明](https://learn.chatgpt.com/docs/customization/memories)。

本项目的 `Saver` 已有本地向量库，但主要提供 `add_memory`、`retrieve_context`、精确删除/替换等**显式工具**。代码中没有从对话自动提炼偏好、区分“长期习惯”和“一次性事实”、处理偏好冲突、按场景注入偏好的完整闭环。`terminal.py` 会把消息与分支存进 SQLite，解决“能继续原会话”；SQLite 记录并不自动等于“新会话懂我”。根目录 `INPUT.md` 描述了数学学习中的个人偏好，但它没有被启动流程读取为系统或项目指令。

这个差别对三类场景都重要：学习时能否默认只核对当前证明步骤；计划时能否记住作息和优先级；讨论时能否沿用对证据严谨程度、反驳方式与回答篇幅的偏好。当前项目需要用户反复重述，或手动维护提示词/记忆。

## 5. 项目的独特价值与结论

本项目最有价值的是可控的本地专业流水线：PDF 公式识别、连续课堂转写、LaTeX/TikZ 编译门禁、可查看的本地计划和记忆、可审计的阶段授权。这些比通用聊天更贴合“把数学资料变成可维护产物”。

当前主要产品短板是交互摩擦与持续上下文：让一句直接指令先成为合适的交互模式，再让用户可查看、可更正的偏好可靠进入未来对话。应优先改善这两点，而不是继续增加专家数量。实现顺序和验收方式见[解决方案报告](project_solution_2026-09-25.md)。
