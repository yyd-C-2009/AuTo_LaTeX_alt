# 工作流修正报告

日期：2026-09-21  
范围：Agent 请求循环、Workflow 阶段上下文、取消处理、验收规划与离线回归测试

## 1. 修正结果

已完成针对本次故障链的代码修正。修正后的系统会限制异常请求数量，保留每个 Stage 的专属任务，在超时或取消时明确记录失败，并阻止步骤耗尽被误判为成功。

## 2. 代码改动

### 2.1 恢复可配置的 Agent 步骤预算

- 删除无条件的 `max_step = 20`。
- 默认重新使用 `runtime.agent_max_steps`，当前值为 5。
- 拒绝非正数步骤预算。
- 达到步骤上限后抛出 `AgentStepLimitError`，不再返回 `None`。

### 2.2 增加 API 连续失败熔断

新增运行配置：

- `llm_request_max_failures = 3`
- `llm_retry_backoff_seconds = 1.0`

行为调整：

- 连续失败会记录当前次数；
- 重试间隔按失败次数递增；
- 连续失败达到 3 次后抛出 `LLMRequestError`；
- 任意一次成功请求会清零连续失败计数。

这使持续性 API 故障最多产生 3 次连续请求，而不是继续耗尽全部 Agent 步骤。

### 2.3 保留并注入 Stage 专属任务

- `Stage` 新增 `instruction` 字段。
- 构造工作流时将每个 `stage_tasks[i]["task"]` 写入对应 Stage。
- 运行时以 Stage 指令作为当前专家的直接目标。
- 同时将工作流总目标作为约束补充，避免阶段只见局部而失去整体上下文。
- 上一阶段结果仍作为前置结果传递。

### 2.4 正确处理取消和超时

- 在阶段执行层显式捕获 `asyncio.CancelledError`，将当前阶段标记为 `failed` 并写入取消原因。
- 在工作流层再次捕获取消，将 Task 和 Workflow 标记为 `failed` 后重新抛出。
- 保留外层超时语义，但不再留下新的永久 `running` 记录。

### 2.5 禁止空结果伪成功

阶段没有返回内容时现在会抛出运行错误。步骤耗尽、模型失败或空结果都将进入 Workflow 失败路径，而不会作为空字符串继续推进并标记成功。

### 2.6 收紧独立验收阶段校验

- 验收阶段必须位于索引大于 0 的位置，即前面至少已有一个待验收阶段。
- 将 `math` 加入允许承担验收工作的专家，以支持独立数学复核。
- 验收任务仍必须明确包含验收、验证、检查等关键词。
